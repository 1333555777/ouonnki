02 / WHY SAFE

「安全」具体指什么

这里说的是三件事：你的文件不外传、站点不惹版权麻烦、页面不依赖任何会消失的后端。

隐私安全：文件不出本机

所有工具都通过浏览器本地 API（Canvas / WebAssembly）处理文件， 代码里没有 fetch、XMLHttpRequest 或 WebSocket 把文件内容发出去。 你可以打开浏览器开发者工具的「网络」面板亲自确认：选中文件后不会产生任何上传请求。

合规安全：不碰版权内容

本站是纯工具，不提供、不托管、不存储、不分发任何视频、音频、图片或其他受版权保护的内容。 所有素材由你自行提供，处理完的结果也只保存在你自己的设备上。

运行安全：静态站点，可离线自审

整站只有 HTML、JS 与 WebAssembly 文件，没有服务端代码、没有数据库、不写 Cookie、 不做统计追踪。你可以把整个目录下载下来离线打开，逐行检查它在做什么。

传输安全：HTTPS 强制

部署在 GitHub Pages 上时默认启用 HTTPS 与 HSTS，全站资源走同源加载， 不引入任何第三方脚本、字体或统计 SDK，避免供应链风险。

03 / DEPLOY

放到 GitHub Pages 上，三步

和 1333555777.github.io 一样，一个仓库、一次推送，就有一个带 HTTPS 的域名。

推送到 GitHub Pages

  1. 在 GitHub 新建仓库 你的用户名.github.io（或任意仓库名）。
  2. 把本目录全部文件（含 vendor/）推到 main 分支。
  3. 仓库 Settings → Pages → Source 选 main / / (root)，保存。
  4. 等一两分钟，访问 https://你的用户名.github.io 即可。

如果仓库名不是 用户名.github.io，站点地址会是 https://用户名.github.io/仓库名/；页面里全部使用相对路径，子目录部署同样正常。

其它静态托管

Cloudflare Pages、Vercel、Netlify、腾讯云 EdgeOne Pages、Gitee Pages 都能直接托管本目录，只需把构建命令留空、输出目录设为根目录。

唯一要注意：音视频引擎通过 Web Worker 加载， 必须用 http(s) 打开，不要直接双击 index.html （浏览器会屏蔽 file:// 下的 Worker）。本地预览可执行 python -m http.server 8765 后访问 http://localhost:8765。
