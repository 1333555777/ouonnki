跨域代理搭建指引

多数片源接口不允许浏览器直接跨域访问（CORS）。搭一个自己的代理后， 把地址填进站点的「片源设置 → 代理前缀」，就能直连任意源。 下面两个方案挑一个：Cloudflare Worker（长期在线，免费）或本地 Python 代理（不用注册任何账号）。

为什么需要它

浏览器有一条同源策略：网页只能请求同源的接口。你填的片源是别人的域名， 直接请求会被拦下来（控制台里能看到 CORS policy 报错）。 代理做的事很简单：替你去取数据，然后加上允许跨域的响应头再交给页面。

本代理还多做了两件对播放很关键的事：透传 Range 请求（否则视频不能拖动进度条）、 改写 m3u8 里的分片地址（否则只有第一层能过代理，分片还是会跨域失败）。

方案 A · Cloudflare Worker（推荐）

  1. 新建一个 Worker
    登录 Cloudflare → Workers & Pages → Create → Worker → Start with Hello World! → Deploy， 先随便起个名字，例如 ouonnki-proxy。
    Workers & Pages
    Overview · Logs · Quick Edit
    点右上角 Quick Edit（或 Edit Code）进入编辑器
  2. 粘贴代码
    把编辑器里原来的内容全选删掉，粘贴下面这份（点右上角「复制代码」）： 
    // 加载中…
    直接下载 proxy-worker.js
  3. 部署
    点右上角 Save and Deploy。
  4. 拿到地址并填进站点
    部署成功后会显示 https://ouonnki-proxy.你的账号.workers.dev。 回到影视站点 → 右上角片源设置 → 代理前缀 填： 
    https://ouonnki-proxy.你的账号.workers.dev/?url=
    结尾的 ?url= 必须带，而且要是英文问号。填错会变成「拼出来的地址 404」。
  5. （强烈建议）加域名白名单
    Worker 页面 → Settings → Variables → Add variable，名字填 ALLOWED_HOSTS，值填你自己的片源域名，多个用英文逗号分隔： 
    a.com,b.com
    留空表示不限制——那样任何人都能拿你的 Worker 当公开代理，流量会被薅。

方案 B · 本地 Python 代理（不用注册）

只想在本机试试、或者暂时不想用 Cloudflare，用这个。只需要装了 Python 3。

  1. 下载 proxy_local.py， 放到任意文件夹。
  2. 在该文件夹打开命令行，执行： 
    python proxy_local.py
# 或指定端口：python proxy_local.py 9000
  3. 看到提示后，在站点「片源设置 → 代理前缀」填： 
    http://127.0.0.1:8787/?url=
这个脚本只监听 127.0.0.1，外网访问不到；关掉窗口就停止。 注意它不能代理本机地址（脚本里做了内网拦截，防止被当成攻击跳板）， 所以它只适合代理公网上的片源。

自检：确认代理真的通了

把地址换成你自己的，在浏览器里打开，应该看到一段 JSON：

https://ouonnki-proxy.你的账号.workers.dev/

用命令行测真实转发（返回一堆 m3u8 文本，且里面的地址都变成你的代理地址，就说明改写生效了）：

curl "https://ouonnki-proxy.你的账号.workers.dev/?url=https%3A%2F%2Ftest-streams.mux.dev%2Fx36xhzz%2Fx36xhzz.m3u8"

常见问题

填了还是搜不到？先确认代理前缀以 ?url= 结尾；再确认片源地址本身在浏览器里能打开。 设置里保存后，页面会用「代理前缀 + 编码后的片源地址」重新发起请求。

能搜索但播放不了？通常是 m3u8 的分片没走代理。本代理已自动改写； 如果你的源用了 AES-128 加密，密钥地址（URI=""）也会被一起改写。

提示 403 域名不在白名单？把该片源域名加进 ALLOWED_HOSTS， 只填主域名即可（填 a.com 会同时放行 www.a.com）。

会被别人滥用吗？设置了白名单就不会。脚本还内置了内网地址拦截 （127.x / 10.x / 192.168.x / 169.254.x 等一律拒绝），不会被当成内网扫描跳板。
